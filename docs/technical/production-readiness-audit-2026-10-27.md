## Резюме

**Статус: не рекомендую объявлять сайт полностью готовым к широкому запуску.** Основной каталог доступен, живой Worker отвечает на ключевые страницы, а последний CI зелёный. Но это не заменяет реальный release gate: main не защищена, pipeline только собирает и выполняет dry-run, часть защиты зависит от настроек Cloudflare вне репозитория, а CSP, ограничение частоты запросов и полноценная проверка пользовательских сценариев не закрыты этим аудитом.

Это аудит репозитория и ограниченная проверка доступной production-версии, не пентест, не полный браузерный/нагрузочный тест и не юридическое заключение.

## Обнаруженные риски и необходимые действия

### P0 — перед широким запуском

1. **Ветка `main` не защищена.** GitHub API возвращает `protected: false`; обязательные проверки не требуются. Ошибка может попасть в production без обязательного review/CI gate. Нужна настройка Branch protection/ruleset: запрет прямых push (кроме утверждённого emergency-процесса), PR и обязательный успешный CI. Из доступных здесь GitHub-действий нельзя безопасно изменить настройки защиты ветки, поэтому этот пункт не объявляется исправленным.
2. **Не подтверждён release/deploy gate.** Workflow заканчивается dry-run и сам по себе не доказывает, что конкретная версия уже развёрнута на Worker. Нужны отдельные подтверждённые сведения о deployed version/commit и post-deploy smoke-check после релиза.
3. **Нет Content-Security-Policy.** В `src/lib/security-headers.ts` отсутствие CSP явно задокументировано из-за inline bootstrap-кода и Telegram/video embeds. Не добавлял случайный blanket-policy, который может сломать логин/плеер; нужна отдельная работа с nonce/hash, allowlist и браузерной регрессией.
4. **Нет подтверждённого edge rate limiting.** Публичный `GET /api/kodik` инициирует запрос к upstream API для заданного ID и не имеет явного приложения-лимитера. Ограничения частоты на Cloudflare edge не удалось подтвердить; нужен rate-limit rule для Kodik и подходящих auth/webhook маршрутов с контролем ложных срабатываний. В этой сессии подключённого Cloudflare API для настройки правила нет.
5. **Постоянный домен не выбран.** SEO canonical и Sitemap используют временный `workers.dev` origin. Для публичного брендовго запуска нужен выбранный домен и финальная проверка canonical/OG/Sitemap/redirects. Это не исправляется угадыванием домена.

### P1 — нужно закрыть до объявления широкой доступности

6. **Демо-функции должны оставаться явно обозначенными.** В текущем UX есть сценарии, которые не эквивалентны полному продукту: полноценный собственный/встроенный видеоплеер всех серий, облачная история и синхронизация не являются полностью завершёнными по README/статусу проекта. Не описывать их как гарантированно работающие функции в объявлении запуска.
7. **Ограниченная production-проверка не равна regression suite.** Главная, профиль, robots.txt и sitemap проверены read-only. В этой сессии не удалось выполнить полный интерактивный тестовый прогон в RU/EN, мобильном/desktop viewport, логине/регистрации, согласии cookies/GPC, плеере и доступности с клавиатуры/screen reader.
8. **Исторический PR #95 остаётся открытым и конфликтным.** Он базируется на старом main и содержит пересекающиеся изменения, часть которых уже влита PR #96–#99; GitHub сообщает `mergeable_state: dirty`. Его надо вручную пересмотреть и закрыть/перебазировать после подтверждения, что в нём не осталось уникальных исправлений. Автоматически вливать его нельзя.
9. **Инвентаризация секретов неполная.** По текущему дереву и доступному code search подозрительных env-файлов/очевидных литеральных секретов не найдено, но полную историю Git и GitHub secret-scanning/Dependabot alerts проверить данным соединением не удалось. Не считать это доказательством отсутствия когда-либо опубликованных секретов.

## Уже существующие защитные меры, которые стоит сохранить

- HTTPS redirect и HSTS на HTTPS.
- Same-origin защита для чувствительных Telegram/auth/admin POST-операций.
- Проверка Telegram initData и OIDC flow.
- Короткие таймауты внешних запросов, ограничение размера некоторых JSON-запросов.
- Ограниченная проксификация изображений Shikimori с allowlist, отказом от redirects, ограничением размера и без передачи upstream cookies.
- Явный opt-in для внутренней аналитики и поддержка Global Privacy Control в текущей реализации.
- Валидация доменов внешнего плеера Kodik.
